Every block, every time

The four rules

They are in the syllabus, on every AI Block slide, and at the bottom of every So-What tab. They are also the rules for the rest of your career.

  1. 1

    Verify

    The tool can be confidently wrong. Every number it gives you gets checked against your own workbook before you believe it. If the tool and your workbook disagree, the tool is wrong until proven otherwise.

  2. 2

    Cite

    Name the tool, give an APA reference, and say in one or two sentences what you used it for. It goes in the So-What tab with your prompt and the output.

  3. 3

    Add value

    You scope the problem by hand: which numbers, which question, which test, which tail. The AI builds. Then you write the manager sentence yourself. The tool never writes it for you.

  4. 4

    Never on quizzes or exams

    No AI tool, in any capacity, on the module quizzes, the midterm, or the final. This is the course rule and the Honor Code.

One per module, 20 minutes each

The seven AI Blocks

Each block builds something small and working with that module's statistic, then tests whether the tool made the classic mistake. The number under each card is what your workbook says; the tool has to match it.

Module 1

Base-rate explainer

The fraud-flag problem: 2% fraud, 90% catch rate, 5% false alarms. Why a flagged order is usually not fraud, explained to a finance manager.

Verify: P(fraud given flag) = .27

Module 2

Demand simulator

Walk-ins at a registration desk, 12.5 an hour. The tool must name the distribution before computing, then price the staffing choice.

Verify: P(more than 15) = .19

Module 3

CI calculator

A confidence-interval calculator that writes its own sentence. You catch it if it says "95% of residents earn between."

Verify: $3,234.45 to $3,563.35

Module 4

One-sample readout

All seven steps of a hypothesis test in business language. You give it the tail before the data and check whether it stays honest.

Verify: t = 1.90, p = .038

Module 5

A/B test readout

Step zero (paired or independent), the right test, the interval, and ship or hold. Then you feed it paired data without saying so.

Verify: t = 2.53, p = .016

Module 6

Group-comparison readout

One ANOVA, not six t-tests. Tukey only when the F test says so. Then the clinics, where the right answer is to stop.

Verify: F = 76.51; then F = .71

Module 7

Segment-association audit

Two categorical columns to a tested table. Does the tool check expected counts before it tests, and explain how it combined categories?

Verify: chi-square = 9.42

The same shape every time

How a block runs

  1. 1

    You state the task

    Which numbers, which question, which distribution or test, which tail. Fill in the square brackets in the prompt. If you cannot fill them in, the method sheet for the module tells you how to decide.

    Say to your AIrun AI Block 3
  2. 2

    The tool builds

    A calculator, a simulator, a readout. Real code, run for real, with the assumption it made stated before the numbers.

  3. 3

    You verify

    Run the course data through it and compare with your workbook. Every module has one classic mistake the tool is likely to make; the module brief tells you what to look for.

  4. 4

    You cite

    Paste prompt, output, verification, and citation into the So-What tab using the module's paste template.

  5. 5

    You write the manager sentence

    One line: the decision, the evidence in business units, the honest confidence, and what it does not prove. Yours, in your words.

    Say to your AIcheck my sentence for the classic errors

  • You are checking a sentence against the classic-errors list.

Prompts you can paste

One prompt per block. Upload the data file, replace the square brackets with your own words, paste the whole thing. The "do not write my recommendation" line at the end is the point; keep it.

1Base-rate explainer (Module 1)

Data: No file needed. Verify against: P(fraud given flagged) = .27; 180 true flags, 490 false flags, 670 flags.

I am a business statistics student. Build me a base-rate explainer and check it
against my numbers.

The situation: [DESCRIBE THE FLAG OR TEST IN ONE SENTENCE, e.g. "an online
retailer's fraud detector flags orders for review"].
Base rate: [2]% of all cases actually have the condition.
Catch rate: the detector flags [90]% of true cases.
False-alarm rate: it also flags [5]% of cases that do not have the condition.

Do this in order:
1. Say back the three rates in a plain sentence so I can confirm them.
2. Build a tree of 10,000 cases: how many have the condition, how many of those
   are flagged, how many do not, how many of those are flagged anyway. Show every
   count. Do not round the counts.
3. Compute P(condition given flagged) as a fraction of the flagged count, and
   P(condition given not flagged).
4. Explain the result to a finance manager in four to six sentences. Lead with
   the counts, not the probability. Say in one sentence why a rare condition
   makes most flags wrong. Say what the number is NOT: it is not the detector's
   accuracy, and it is not the share of the time the detector is wrong.
5. Give me a small calculator (a table or a short function) that takes the three
   rates and returns the tree and P(condition given flagged). Show it on two
   other base rates so I can see the base rate move the answer.
6. List what my one-line recommendation to the manager must contain. Do not
   write the recommendation; I write it.

Round like this, because I am graded on it: probabilities, proportions and test
statistics to two decimals with no leading zero (.34, t = 2.53); p-values to three
decimals with no leading zero (p = .038), and p < .001 below that; money to the cent;
critical values to three decimals. Show each value unrounded once, then rounded.

4One-sample test readout (Module 4)

Data: DeniceToney_Balances.csv. Verify against: t = 1.90, p = .038, reject; two-tailed against $2,800: t = -1.88, p = .079.

I am a business statistics student. Build me a hypothesis-test readout for one
sample and check it against my numbers. Do NOT look at the data until you have
recorded the tail in step 1.

1. Record these before opening the data:
   Parameter in words: [THE TRUE MEAN BALANCE OF MID-TIER ACCOUNTS].
   Claimed value (H0): [2500].
   Tail, chosen from the business question: [RIGHT-TAILED, because the manager
   funds the promotion only if the mean is ABOVE 2500].
   Alpha: [.05].
2. Now the data: the attached file, column [Account balance ($)]. (Or: n = [16],
   mean = [2650.68], sd = [317.11].)
3. Write out all seven steps: parameter; H0; Ha with the tail; the statistic and
   its degrees of freedom; alpha, the critical value, and a description of the
   rejection picture; the computed statistic and p-value; the decision and its
   interpretation in business language. Next to each computed value, the Excel
   function (AVERAGE, STDEV.S, T.INV, T.DIST.RT, T.DIST.2T).
4. Then run the two-tailed version against [2800] and show that the two-tailed p
   is double the one-tailed p for the same statistic, and why.
5. Give the 95% confidence interval for the mean and explain in two sentences why
   the claimed value can sit inside a two-sided interval while a one-sided test
   still rejects it.
6. Say what the result does NOT prove. Never write "accept H0" and never write
   "proves."
7. List what my one-line recommendation must contain. Do not write it.

Round like this, because I am graded on it: probabilities, proportions and test
statistics to two decimals with no leading zero (.34, t = 2.53); p-values to three
decimals with no leading zero (p = .038), and p < .001 below that; money to the cent;
critical values to three decimals. Show each value unrounded once, then rounded.
5A/B test readout (Module 5)

Data: Streamly_ABTest_CX.csv, then Multitasking_Example14.csv in a new chat. Verify against: Streamly t = 2.53, p = .016, CI .16 to 1.44; multitasking is paired, t = 12.52, p < .001.

I am a business statistics student. Build me an A/B test readout and check it
against my numbers.

Data: the attached file. Group column: [Variant]. Score column: [CX score
(1 to 10)]. (For a file with two score columns and no group column, use the two
columns.)
The business question: [IS THE NEW ONBOARDING FLOW BETTER OR WORSE THAN THE
CURRENT ONE] (so the tail is [TWO-TAILED]). Alpha [.05].
My practical threshold: the difference would have to be at least [0.5] points to
be worth shipping.

Do this in order:
1. Step zero: decide whether the two groups are paired (the same unit measured
   twice, linked row by row) or independent (different units), and give the
   evidence for your decision from the data itself: the row identifier, the
   column names, and whether the differences are much less variable than either
   column. If you cannot tell, ask me; do not guess.
2. State the parameter in words, H0, Ha with the tail, alpha.
3. Run the right test. For independent groups use the Welch t-test (do not pool
   variances) and report the p-value two ways: with the conservative degrees of
   freedom (smaller n minus 1) and with the Welch degrees of freedom. For paired
   data, analyze the column of differences. Show every intermediate value and
   the Excel function next to it (T.TEST with type 3 or type 1, T.INV.2T).
4. Report the difference, its standard error, the statistic, the degrees of
   freedom, the p-value, and the 95% confidence interval for the difference,
   together.
5. Place my practical threshold against the interval and tell me which of these
   applies: whole interval above the threshold (ship); interval straddles it
   (iterate or extend); whole interval below (hold); interval includes zero and
   is narrow (hold, no meaningful effect); interval includes zero and is wide
   (inconclusive).
6. List what my ship-or-hold recommendation must contain. Do not write it.

Round like this, because I am graded on it: probabilities, proportions and test
statistics to two decimals with no leading zero (.34, t = 2.53); p-values to three
decimals with no leading zero (p = .038), and p < .001 below that; money to the cent;
critical values to three decimals. Show each value unrounded once, then rounded.

I am a business statistics student. Build me a group-comparison readout and check
it against my numbers.

Data: the attached file, one column per group: [OR Analyst, Accountant, Computer
Analyst, Financial Specialist]. What is measured: [STARTING SALARY IN DOLLARS].
Alpha [.05].

Do this in order, and do NOT run pairwise t-tests at any point:

check it against my numbers.

Data: the attached file, one row per guest. Column A: [Primary activity]. Column

Common problems

If you get stuck

The tool's number does not match my workbook
The tool is wrong until proven otherwise. The usual causes: z instead of t, a tail chosen after the data, pooled instead of Welch, expected counts not checked, or an intermediate value rounded. Say which one you found in your verification block.
The tool wrote my recommendation anyway
Do not paste it. Take the numbers, write your own sentence, and note in the verification block that the tool overstepped. That is a legitimate and common finding.
My chat allowance ran out
Switch to another free tool for this block. Credits reset on the first of the month, and you never need to buy any. Using Ask rather than Agent for small questions is what makes an allowance last.
I do not know whether to use Ask or Agent
Ask for anything small: one question, one formula, one sentence you want checked. Agent when the block needs code run, or when you want the output written to 2_Outputs. The full rule is in Ask or Agent?.
I cannot get the workspace onto my computer
You do not need it. Every block works from the paste prompts on a chat tool. If you do want the folder, the three setup prompts are in Set up Tier 2 once.
I do not know which test my project data needs
One group against a number is Module 4; two groups is Module 5; three or more is Module 6; counts in categories is Module 7. The method sheets walk each one.
Something in the workspace looks wrong
Tell your instructor. The course has a lot of moving parts and bug reports are welcome.

Plain language

Words we will use

AI Block
The 20-minute build at the end of each module: state the task, have the tool build, verify, cite, write the sentence.
Manager sentence
The one line that states the decision the analysis supports, written for someone who will not open the workbook. Always yours.
Base rate
How common something is before any test or flag. When it is rare, most flags are wrong even with a good detector.
Standard error
How much a sample statistic would move from sample to sample. The spread of the sampling distribution.
Confidence interval
A range for a population number, with a confidence level that describes the method, not the individuals. "We are 95% confident the true mean is between..."
p-value
If the claim in H0 were true, the chance of seeing a result at least this far from it. Small p is evidence against the claim. It is not the chance the claim is true.
Tail
Whether the business question asks "above," "below," or "different." Chosen from the question, before the data.
Paired versus independent
Paired: the same unit measured twice. Independent: different units in each group. Step zero of every two-sample test.
Welch t-test
The two-sample t-test that does not assume equal spreads. The course default.
ANOVA
One test for whether three or more group means differ, so the false-alarm rate does not pile up across many t-tests.
Tukey HSD
The follow-up after a rejected ANOVA that says which pairs of groups differ. Never run after a failed F test.
Expected count
What a cell in a table of counts would hold if the two variables were unrelated. Every one must be at least 5 before a chi-square test.
Chi-square
The test for counts: does an observed mix match a claim (goodness of fit), or are two categorical variables related (independence).
Skill
A markdown file in the workspace that tells an agent exactly how to run one AI Block. You do not need to read them; they exist so the tool behaves the same for everyone.
Agent
An AI tool that can read your folder and run code, like Claude Code or Copilot agent mode. A chat window is not an agent, and the course does not require one.
